# 玩法总览

**适用场景**: 需要理解第一版涌现玩法目标、玩家爽点和 MVP 边界时.

## 一句话

玩家扮演武侠帮派领导, 用少量宏观指令干预一个会自行收税、争地、背叛、复仇和闹笑话的江湖模拟系统.

## 第一版目标

- 先验证后端日志的基础可玩性, 不依赖 UI、人物立绘或地图表现.
- 使用固定 seed 和离散 Tick 跑出可复现事件流.
- 让经济压力、角色欲望、关系记忆和战斗结果互相放大, 产生荒诞但可追溯的故事.
- 输出开发者愿意截图分享的日志片段, 作为后续 UI 和人物设计依据.

## 玩家体验

- 玩家不是实时操控单个角色, 而是观察帮派生态并做有限干预.
- 爽点来自“严肃规则导致荒谬结果”: 裁员救急引来敌帮扩军、奖励功臣诱发嫉妒、惩罚叛徒导致家属举报.
- 成败判断先让位于故事密度、关系连锁和日志可读性.

## MVP 边界

必须包含:

- 3 个帮派、6 个地盘、24-36 个角色.
- 经济、决策、行动、战斗、关系、事件、日志的完整 Tick 链路.
- 5 类玩家宏观指令: 扩张、防守、奖励、处罚、招募.
- 结构化事件流和可读日志输出.
- 30-100 Tick 的固定 seed 验收.

暂不包含:

- 精细 UI、人物美术、复杂地图、联网、技能树、外部 AI Agent.
- 实时战斗微操.
- 无规则支撑的纯剧情脚本.
